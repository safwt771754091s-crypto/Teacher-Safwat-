# طبقة وكلاء الذكاء الاصطناعي — معلمي الذكي اليمني

هذه الوثيقة تشرح كيف تعمل «الوكلاء» في المنصة، وكيف نضمن أنها تعمل **بدون إنترنت**
وأنها لا تخترع محتوى من خارج الكتاب المدرسي.

## الفكرة

كل مهمة في المنصة ينفّذها **وكيل واحد مسؤول عنها** (Agent). الوكيل:

- له مفتاح ثابت (`key`) واسم عربي وهدف واضح.
- يستقبل **سياقًا** (`AgentContext`): المستخدم، والكيان الذي يعمل عليه (درس/تمرين/كتاب)،
  ومعاملات إضافية.
- يُرجع نتيجة موحّدة (`AgentResult`) بحالة واحدة من ثلاث:
  - `ok` — نجح وأرجع مخرجات حقيقية.
  - `needs_content` — لا يملك محتوى معتمدًا، فيتوقف ويطلب المحتوى **بدل التخمين**.
  - `error` — خطأ تقني.
- كل تشغيل يُسجَّل في جدول `agent_runs` (الحالة، الوضع سحابي/بدون إنترنت، عدد العناصر،
  المدة، المستخدم) لتراه لوحة المالك.

## الوكلاء الحاليون

| المفتاح | الاسم | المهمة | بدون إنترنت |
|---|---|---|---|
| `book-importer` | وكيل استيراد الكتب | تحميل كتب المنهج، استخراج النصوص (OCR)، إنشاء الدروس المسودة | ✅ |
| `curriculum-builder` | وكيل بناء المنهج | إنشاء الصفوف والمواد لكل المراحل (ابتدائي → ثانوي) | ✅ |
| `lesson-explainer` | وكيل شرح الدروس | شرح الدرس من مصدره بلغة مناسبة للعمر والرد على الأسئلة | ✅ |
| `exercise-solver` | وكيل حل التمارين | حل نماذج التمارين خطوة بخطوة مع شرح الطريقة | ✅ |
| `audio-narrator` | وكيل التسجيل الصوتي | تجهيز نص السرد للاستماع (النطق يتم على الجهاز) | ✅ |
| `content-reviewer` | وكيل مراجعة المحتوى | فحص الدروس والتمارين المستخرجة وكشف النواقص قبل الاعتماد | ✅ |

## مبدأ «بدون إنترنت» (Offline-first)

- لا يوجد أي وكيل **يحتاج** مزوّد سحابي. عندما لا يوجد مزوّد مُهيّأ
  (`platform.ai.provider = none`) يعمل كل وكيل اعتمادًا على:
  - **المحتوى المُستخرج من الكتاب** (نصوص الصفحات المعتمدة)، و
  - **الحساب البرمجي** للإجابات الرقمية (`NumericVerifier`)، و
  - **نطق الجهاز** للصوت (`SpeechSynthesis` في المتصفح/الهاتف).
- عند تهيئة مزوّد سحابي، يُستخدم النموذج **فقط لإعادة صياغة** محتوى مُسترجع مسبقًا من
  الكتاب، لا كمصدر للحقيقة. الخدمة الوسيطة `OfflineAiService` تُرجع دائمًا بديلًا
  حتميًا (deterministic) إذا فشل الاتصال، فلا تتوقف المنصة.

## كيف يُنفَّذ وكيل؟

```bash
# عبر الواجهة البرمجية (يتطلب مصادقة)
curl -X POST http://HOST/api/v1/agents/exercise-solver/run \
  -H "Authorization: Bearer TOKEN" -H 'Content-Type: application/json' \
  -d '{"subject_type":"exercise","subject_id":1}'
```

```php
// برمجيًا
$result = app(\App\Agents\AgentRegistry::class)
    ->run('lesson-explainer', new \App\Agents\AgentContext($user, $lesson, ['question' => '...']));
```

## الصلاحيات

- `book-importer` و`curriculum-builder` و`content-reviewer` — **للمعلم والمشرف والمالك فقط**
  (تمسّ المنهج والمحتوى).
- `lesson-explainer` و`exercise-solver` و`audio-narrator` — متاحة لأي مستخدم مُصادق.

## نقاط API

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/agents` | قائمة الوكلاء + جاهزية العمل بدون إنترنت |
| GET | `/api/v1/agents/targets` | دروس وتمارين مقترحة لتشغيل الوكلاء عليها |
| GET | `/api/v1/agents/runs` | سجل التشغيل (آخر 50) |
| POST | `/api/v1/agents/{key}/run` | تشغيل وكيل |
| GET | `/api/v1/config` | يحتوي حقل `offline` بجاهزية المنصة |

## توسيع المنصة لاحقًا (خارطة الطريق)

طبقة الوكلاء مبنية لتستقبل وكلاء جدد بنفس العقد دون تغيير الواجهات:

- **وكيل السيرة النبوية** (`seerah-agent`) — دروس السيرة من مصدر معتمد.
- **وكيل تحفيظ القرآن** (`quran-agent`) — الآيات، التلاوة، والتحفيظ المرحلي.
- **وكيل الحديث** (`hadith-agent`) — نص الحديث + الراوي + درجة الصحة (صحيح/متفق عليه/مختلف فيه).
- **وكيل الدعوة** (`dawah-agent`) — محتوى دعوي موجّه.

كل وكيل جديد يلتزم بقاعدة واحدة: **من المصدر، وإلا `needs_content`**.
